nginx-sentinel стежить за nginx access.log у реальному часі, оцінює кожен IP через 7 поведінкових детекторів і передає підтверджені загрози напряму до Fail2Ban.

Виявлення загроз

7 детекторів — один score

Кожен детектор додає очки до рахунку IP. Score затухає лінійно за час observation_window — жодних хибних банів від старого трафіку.

🔍

Probe — зондування

Запити до чутливих шляхів: /.env, /.git/config, /.aws/credentials, /wp-config.php, /phpinfo.php, панелі адміністратора, backup-архіви та ще 30+. Ці шляхи не мають сенсу для легітимного відвідувача — будь-яке звернення є активною розвідкою. Спрацьовує миттєво на першому запиті, без порогових умов.

+25 за запит
⚡

Rate — аномальна частота

Понад 100 запитів за 60 секунд з одного IP — відстежується через ковзне вікно. Виявляє DDoS-зондування, агресивні сканери вразливостей, сплески підбору облікових даних та скрепери, які намагаються триматися нижче статичних обмежень. Поріг і вікно повністю налаштовуються.

+25
🤖

User-Agent — підозрілий клієнт

Регістронезалежне збігання підрядка з трьома вбудованими списками: сканери (Nuclei, sqlmap, Nikto, Nessus, Acunetix…), грабери (Scrapy, HTTrack, wget…) та інструменти автоматизації (python-requests, curl, Go-http-client…). Кожна категорія має свій налаштовуваний score. Розширюйте вбудовані списки через extra_*_patterns у конфігу — без змін коду.

+15 до +40
🔐

Bruteforce — перебір

Понад 60% відповідей — 404 при мінімум 10 запитах у вікні спостереження. Типова сигнатура інструментів перебору шляхів (dirbuster, gobuster, ffuf), що сліпо обходять словники у пошуку прихованих файлів і панелей адміністратора. Поріг min_requests запобігає хибним спрацьовуванням від користувачів, які помилилися в URL.

+30
📄

Crawler — послідовний обхід

П'ять і більше послідовно пронумерованих URL підряд — /page/1, /page/2, /article/100, /article/101… Характерна ознака автоматичних скраперів, що дампять цілі розділи сайту по порядку. Реальна людина не обходить URL у суворій числовій послідовності з машинною швидкістю.

+20
🖼️

No-asset — бот без рендерингу

Завантажує сторінки, але запитує CSS, JS або зображення менш ніж у 10% випадків — при мінімум 3 переглядах сторінок. Кожен реальний браузер завантажує ресурси, зазначені в HTML. Боти, що парсять лише розмітку (headless-скрепери, агрегатори, збирачі посилань), повністю пропускають статику — детектор ловить їх, не зачіпаючи легітимний трафік.

+20
💣

Overflow — WAF bypass

URL довший за 2048 символів або такий, що містить відомі WAF bypass ключові слова: bypass, shell, cmd, eval, exec, passthru, system. Надвеликі URL зондують вразливості переповнення буфера та ін'єкції параметрів. Ключові слова націлені на PHP shell injection, виконання команд ОС і обхід міжмережевих екранів.

+30
Встановлення

Встановлення в 3 кроки

Пакет робить все сам: бінарник, systemd unit, Fail2Ban filter/jail, logrotate та системного користувача nginx-sentinel.

Швидке встановлення — автоматично визначає OS та архітектуру: 

curl -fsSL https://raw.githubusercontent.com/mr-addams/nginx-sentinel/main/scripts/get.sh | sudo bash

Підтримує Debian, Ubuntu, Fedora, RHEL, AlmaLinux, Rocky Linux, Arch Linux · amd64 та arm64

Встановлення скриптом
З вихідного коду
# Працює на Debian, Ubuntu, Fedora, RHEL, AlmaLinux, Rocky Linux, Arch Linux
# Скрипт сам визначає дистрибутив і архітектуру (amd64 / arm64)
curl -fsSL https://raw.githubusercontent.com/mr-addams/nginx-sentinel/main/scripts/get.sh | sudo bash

Скрипт завантажує потрібний пакет з GitHub Releases, встановлює через системний менеджер пакетів, перевіряє наявність fail2ban, автоматично визначає шлях до nginx access.log і запускає сервіс. 

# Потрібен Go 1.19+
git clone https://github.com/mr-addams/nginx-sentinel
cd nginx-sentinel
sudo ./scripts/install.sh
sudo systemctl enable --now nginx-sentinel
Після встановлення: відкрийте /etc/nginx-sentinel/config.yaml і вкажіть шлях до nginx access.log у параметрі general.log_file (зазвичай /var/log/nginx/access.log). Запустіть сервіс. Конфіг перезавантажується по SIGHUP — рестарт не потрібен.

Легітимний трафік ніколи не блокується

Два незалежних механізми захищають ваших реальних відвідувачів і інструменти від хибних спрацьовувань.

🔬

Автоматична верифікація ботів

Googlebot, Bingbot, Яндекс, DuckDuckBot, GPTBot та ще 6 сімейств верифікуються через зворотний + прямий DNS. Легітимні краулери ніколи не отримують очків. Фейкові боти отримують штраф.

✅

Кастомні виключення

Додайте IP офісу, VPN-підмережі (CIDR), сервіси моніторингу або SEO-інструменти за підрядком User-Agent. Зміни застосовуються миттєво по SIGHUP — рестарт не потрібен.

🔄

Гаряче перезавантаження

Всі зміни конфігу — whitelist, очки детекторів, пороги — застосовуються командою systemctl kill -s HUP nginx-sentinel. Стан IP і DNS-кеш зберігаються.
